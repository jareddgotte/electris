next approved channel named in `RELEASING.md` and #38. As of this proposal:

- No release-prepare or release-publish workflow has run for this version.

## Scope of this proposal

This version bump and note are prepared under #41, which scopes only the
version/release-note proposal itself. Preparation (tagging, native packaging,
draft assembly) and publication remain separate, later, separately authorized

## Unresolved readiness prerequisites

The following prerequisites from #38 remain open and must be resolved or
explicitly dispositioned before any public release, independent of this
proposal:

- Dependency-audit findings are unresolved (`npm audit` currently reports 5
  high and 1 critical advisories); a preferred remediation path is focused
  tested React/ReactDOM and Vitest upgrades.
- Native application icon, branding, and trademark review is not complete.
- GitHub private vulnerability reporting is not yet enabled.
- Signing/notarization credentials and the protected `release-signing`
  environment are not configured; macOS artifacts remain draft/qualification
  only until signed and notarized.
- Matching native runner labels/capacity for the full release matrix (Linux
  x64, Windows x64, macOS arm64, macOS x64) are not yet confirmed.
- Administrator rollout (protected `v*` tag ruleset, `release-publish` and
  `release-signing` environments, read-only default workflow token, immutable
  releases after canary recovery) is not yet applied; see
  `docs/release-administration.md`.

## Support and security status

Electris has no current supported release. This prerelease, once published,
would be supported only on a best-effort basis with no response-time SLA,
consistent with `SUPPORT.md`. `SECURITY.md`'s disposition guidance applies
unchanged.

## Migration and rollback

No user-facing gameplay or data-format changes are proposed by this version
bump. Before any tag exists, rollback is a normal revert of the version-bump
commit. After a future tag or publication, correction requires a new SemVer
version; existing tags and published bytes are never moved or replaced.
